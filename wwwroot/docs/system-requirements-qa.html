Contractor Attendance & Health Declaration Monitoring

A web-based system that records contractor attendance through ID-card scanning at a kiosk, applies a self-administered health and waiver gate at entry, and provides administrators with management, correction, and audit tools.

System version2.9.11.0
Document date26 August 2026
AudienceManagement, QA, and development
PlatformASP.NET Core 8 MVC · MySQL (stored procedures via Dapper) · SignalR · LDAP
SECTION 01

System overview

Contractors scan their ID card at an unattended kiosk. Each scan is either a TIME IN (starts an attendance session) or a TIME OUT (closes the open session). On TIME IN the contractor completes a short self-declaration — health status and waiver consent — within a configurable window. Combinations that mean "not allowed to enter" automatically close the session. Administrators manage reference data (providers, projects, contractors), correct attendance records, and every admin change is audit-logged.

User roles

RoleAuthenticationCapabilities
ContractorNone — kiosk is publicScan ID; declare health status & waiver consent within the window
Public viewerNoneView, filter and export attendance history logs
AdminLDAP login + membership of configured AD group; 30-minute sessionManage providers, projects, contractors (incl. bulk import), system configuration; edit/delete timelogs; view audit logs

Status vocabulary

  • Health status: FIT or UNFIT — stored as a MySQL ENUM on the attendance record.
  • Waiver consent: UNDERSTOOD or NOT_UNDERSTOOD.
  • "Not allowed to enter" combination = UNFIT or FIT + NOT_UNDERSTOOD. Both auto-set a TIME OUT and block same-day re-entry.
SECTION 02

System requirements

What the system must enforce, grouped by module.

Kiosk scanning

  • Scan input accepts typed or keyboard-wedge scanner input; it autofocuses, clears, and refocuses after every attempt, and can be locked read-only for scanner-only operation (ScanInputReadOnly).
  • The scan input is cleared the moment a scan is submitted, and scanner-burst detection resets after each scan — a scan that starts while the previous request is still in flight is captured intact (no dropped first character).
  • Unknown employee ID is rejected with no record written; inactive contractors are rejected.
  • A scan within DebounceThresholdSeconds of the contractor's last scan event is rejected as a duplicate.
  • A blocked combination on today's latest TIME IN blocks all further scans that day, until an admin corrects the record.
  • TIME IN requires the contractor's project and provider to exist and be active; an open session always allows TIME OUT.
  • A passing TIME IN creates a record with time_in = now, time_out = NULL, defaulting to FIT + UNDERSTOOD.

Health declaration & waiver

  • Two instant-save controls — health status and waiver consent — pre-selected to the safe defaults; sickness items come from configuration.
  • Changes are accepted only within HealthDeclarationWindowSeconds of TIME IN (server-enforced; falls back to 120 s).
  • UNFIT or FIT + NOT_UNDERSTOOD persists, sets time_out = now, and blocks same-day re-entry.
  • Returning to FIT + UNDERSTOOD within the window clears the auto-set time_out and reopens the session.
  • After the window the declaration is locked; only an admin correction can change it.

History logs

  • Public read-only listing with filters: date range and health status (AND logic).
  • Client-side Excel export contains exactly the filtered rows; the export button is hidden when the result set is empty.

Authentication & session

  • Admin login authenticates against corporate LDAP and requires membership of the configured AD group.
  • Sessions use an HTTP-only cookie with a 30-minute idle timeout; all /Admin/* pages and JSON endpoints are protected.
  • Logout clears the session; audit entries record the admin's employee number.

Providers & projects

  • Provider code is auto-generated from the provider name (acronym, with unique fallbacks); it is never typed manually.
  • Project code is generated as {ProviderCode}-{YY}-{NNN}, sequential per provider per year, transaction-safe against duplicates.
  • A project requires its provider, name, PIC, contact number, and contract start/end dates; end must not precede start, and a past end date is rejected on creation.
  • Projects past their contract end auto-deactivate, cascading to their contractors; restore via cascade reactivation brings back only the cascade-deactivated contractors — manually deactivated ones stay inactive.
  • A project whose contract has expired cannot be set back to Active until the contract end date is extended.
  • Projects are soft-deleted (hidden, never removed) and cascade-remove their enrollments; providers have no delete operation — only activation status. Inactivity blocks TIME IN but not TIME OUT.

Contractors

  • Employee ID is generated automatically as {ProjectCode}-{NNNN} when saving (read-only in the form). Required fields: name, gender, birthdate, position, area of destination, provider, and project — the project must belong to the chosen provider. Contact number and address are optional.
  • Birthdate must not be a future date, and the contractor must be at least 18 years old — The employee is under 18 years old and is not eligible for employment under DOLE regulations.
  • Duplicate enrollment is blocked on same name (case-insensitive) + birthdate in the same project (active or inactive enrollments both count) — including rows committed earlier in the same bulk batch.
  • Bulk Excel import commits valid rows and reports per-row success/failure (partial success is visible).
  • Contractors are deactivated, never hard-deleted; the list supports project/status filters, reset, and Excel export.

TimeLogs management

  • Admins can edit time_in, time_out, health status, and waiver consent on any record at any time — including past the kiosk window.
  • Saving a blocked combination with a blank time_out auto-fills time_out = time_in instead of leaving the session open.
  • Correcting a blocked record to an allowed combination re-enables same-day kiosk entry.
  • Records can be hard-deleted for cleanup after an explicit confirmation; every change is audit-logged and stamped with updated_by/updated_at.

System configuration

  • Business-rule keys are editable at runtime and take effect on the next request — no redeployment or restart.
  • Numeric window keys (DebounceThresholdSeconds, HealthDeclarationWindowSeconds) are validated to 5–300 seconds.
  • AdminADGroup is database-managed and not shown in the configuration UI.
  • Configuration changes are audit-logged.

Audit logging

  • Every admin mutation (provider, project, contractor, bulk import, system config, timelog edit/delete) writes an audit entry with before/after JSON and the acting user.
  • The audit view renders a changes-only diff (old vs. new per changed field).
  • A failed audit write never fails the business operation that triggered it.

SECTION 03

System functionality

How the system behaves end to end.

Attendance cycle

  • Scan — the contractor scans their ID at the kiosk; the server evaluates the scan rules below.
  • TIME IN — a session opens with safe defaults and the health declaration panel appears with a countdown.
  • Declare — the contractor answers the health self-assessment and waiver within the window; changes save instantly.
  • TIME OUT — the next scan after the debounce window closes the session.

Scan rule sequence

Every scan is evaluated in this fixed order; the first failing rule wins. Messages are prefixed with the contractor's name (shown as <name>); only Contractor not found is unprefixed.

StepRulePassFail — exact message
1Contractor existsContinueContractor not found
2Contractor is activeContinue<name> - Contractor is inactive
3Debounce: elapsed ≥ threshold since last scan eventContinue<name> - Duplicate scan - wait N seconds.
4Today's latest TIME IN is an allowed combinationContinue<name> - Not Allowed to Enter. You are UNFIT. / <name> - Not Allowed to Enter. You did not understand waiver.
5Open session?Yes → TIME OUT: time_out = now, <name> - SUCCESS TIME OUTNo → continue
6Project exists and is activeContinue<name> - Not Allowed to Enter. Project is In-Active.
7Provider exists and is activeContinue<name> - Not Allowed to Enter. Provider is In-Active.
8Create TIME INtime_in = now, FIT, UNDERSTOOD; <name> - SUCCESS TIME IN; declaration panel opens—
Ordering matters

The project/provider gates (steps 6–7) deliberately run after the open-session check (step 5): a contractor already on-site can always TIME OUT even if their project or provider was deactivated mid-day.

Health gate

  • On TIME IN the declaration panel opens with FIT + UNDERSTOOD pre-selected and a visible countdown.
  • Selecting UNFIT or NOT_UNDERSTOOD persists immediately, sets time_out = now, shows a critical alert, and blocks same-day re-entry.
  • Reversing to FIT + UNDERSTOOD within the window clears the auto-set time_out and reopens the session.
  • When the countdown reaches zero — or any next scan is submitted — the panel hides and the declaration locks.

Reporting & exports

  • History logs, TimeLogs, and Contractors lists each export to Excel reflecting the active filters.
  • Per-project contractor lists are viewable and exportable from the Projects page.

Code generation

  • Provider code — derived from the provider name as an acronym (e.g. Alpha Circuits Inc → ACI), with deterministic fallbacks that keep codes unique.
  • Project code — {ProviderCode}-{YY}-{NNN} (e.g. ACI-26-005), sequential per provider, resetting to 001 each year, transaction-protected.
  • Employee ID — generated on enrollment as {ProjectCode}-{NNNN}, sequential within the project and stable for the contractor's lifetime on that assignment.

SECTION 04

System manual

How to use the system, by role and task.

Contractor — kiosk

  • Scan your ID card at the kiosk (or type the employee ID and press Enter).
  • On SUCCESS TIME IN, the declaration panel opens — answer the health self-assessment and the waiver before the countdown ends. Untouched answers keep the safe defaults (FIT / I understand).
  • Scan again when leaving to record SUCCESS TIME OUT.
  • While the declaration panel is closed, the right panel shows the company logo (ACI); it hides while the panel is open and returns when the panel closes.
Kiosk messageMeaning
<name> - SUCCESS TIME IN / <name> - SUCCESS TIME OUTSession opened / closed
Contractor not foundID is not enrolled — contact the admin
<name> - Contractor is inactiveEnrollment is deactivated — contact the admin
<name> - Duplicate scan - wait N seconds.Too soon after the last scan; wait and re-scan
<name> - Not Allowed to Enter. You are UNFIT.Declared UNFIT — entry blocked for the day
<name> - Not Allowed to Enter. You did not understand waiver.Waiver not understood — entry blocked for the day
<name> - Not Allowed to Enter. Project is In-Active. / <name> - Not Allowed to Enter. Provider is In-Active.Assignment is inactive — contact the admin

Viewer — history logs

  • /Home/HistoryLogs — filter by date range or health status; export the filtered rows to Excel. No login needed.

Admin — sign in

  • Sign in at /Auth/Login with corporate credentials; your account must be a member of the configured admin AD group.
  • The session expires after 30 minutes of inactivity. Sidebar pages: Dashboard, Projects, Contractors, System Config, TimeLogs (the Audit Logs page is reached by URL at /Admin/AuditLogs).

Admin — dashboard

  • /Admin shows Active Projects, Active Contractors, and On Premises cards plus a Recent TimeLogs table covering the last 7 days.

Admin — manage projects & providers

  • Add New Project: choose or create the provider, then fill the project name, provider PIC, contact number, and contract dates. Provider and project codes are generated automatically.
  • Edit (pencil): update project details; the provider is locked once assigned.
  • View Contractors (count link): lists the project's contractors with an Excel export.
  • Delete (trash): soft-deletes the project and marks its enrolled contractors inactive — the confirmation dialog states this cascade.
  • The Remaining Days column flags projects as Expired; expired projects auto-deactivate.

Admin — manage contractors

  • Add New Contractor: fill the identity fields; the project must belong to the chosen provider, and the employee ID is generated automatically when saving. Duplicates (same name + birthdate on the same project) are rejected.
  • Bulk Import: upload an Excel file, select the provider and project, review the preview, then import — the result lists succeeded and failed rows.
  • Edit: update details or reactivate an inactive contractor.
  • Delete / Delete Selected: deactivates contractors (attendance history is preserved).
  • Filter by project and Active/Inactive status, reset the filters, or export the filtered list to Excel.

Admin — correct attendance (TimeLogs)

  • /Admin/TimeLogs: filter by date range and health status (defaults to the last 7 days); use the table search to find an employee; export to Excel.
  • Edit (pencil): change Time In, Time Out, Health Status, and Waiver Consent on any record.
  • Delete (trash): permanently removes the record after confirmation.

Admin — configure the system

  • /Admin/SystemConfig: edit the configuration keys listed in Section 03 — changes apply immediately. ScanInputReadOnly is a toggle; the waiver text keys preserve line breaks.

Admin — review the audit trail

  • /Admin/AuditLogs: browse admin changes; each entry shows a changes-only diff with the acting admin and timestamp.
